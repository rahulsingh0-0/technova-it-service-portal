# UI Policies

## Objective

Configure UI Policies to dynamically control form fields based on conditions without requiring client-side scripting.

## Purpose

UI Policies can be used to:

- Make fields mandatory
- Make fields read-only
- Show or hide fields
- Apply dynamic form behavior

## Example

A UI Policy can be configured so that when an Incident reaches a specific state, related fields become mandatory or read-only.

## UI Policy Actions

The project demonstrates the use of UI Policy Actions to control individual fields.

Common actions include:

- Mandatory
- Read-only
- Visible

## Testing

UI Policies were tested by changing the relevant field values and verifying that the expected field behavior was applied automatically.

## UI Policy vs Client Script

UI Policies are preferred for simple form behavior that can be achieved through configuration.

Client Scripts are used when more complex client-side logic is required.
