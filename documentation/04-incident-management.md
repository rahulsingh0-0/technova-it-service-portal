# Incident Management

## Objective

Configure and demonstrate the Incident Management process for handling IT service disruptions and user issues.

## Incident Lifecycle

The basic Incident workflow used in the project is:

New → In Progress → On Hold → Resolved → Closed

## Incident Configuration

The project demonstrates working with:

- Incident number
- Caller
- Category
- Subcategory
- Impact
- Urgency
- Priority
- Assignment group
- Assigned to
- Short description
- Description
- State

## Priority

Incident priority is determined using the relationship between:

- Impact
- Urgency

Higher-impact and higher-urgency incidents receive higher priority.

## Assignment

Incidents are assigned to the appropriate support group and technician so that issues can be investigated and resolved.

## Testing

Test incidents were created and updated to verify:

- Incident creation
- Priority calculation
- Assignment
- State transitions
- Resolution and closure

## Skills Demonstrated

- Incident Management
- ITSM workflow
- Priority concepts
- Assignment and routing
- Incident lifecycle management
- Testing and validation
